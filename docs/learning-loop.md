# 学习机制

这份文件是学习机制的规则，也是每周定时任务的操作说明。要改机制，改这里就行，定时任务每次都按这份文件执行。

## 三个地方，各管一件事

| 地方 | 管什么 | 地址 |
| --- | --- | --- |
| 学习路线文档 | 每章讲什么、怎么做实验、验收标准 | https://claude.ai/code/artifact/1942adf9-7675-48e4-b427-242d6e0c4e04 |
| 推进器实验记录页 | 每次测试的数据（含预测值） | https://claude.ai/artifact/EM1s2Lap5BUk9rgaMcAPRz （数据库集合 `runs`） |
| 本仓库 | 进度、每周计划、复盘、配置、原始日志、脚本 | https://github.com/jinbaolu/thruster-lab |

## 每周节奏

| 时间 | 谁 | 做什么 |
| --- | --- | --- |
| 周一早上 | 定时任务 | 生成本周计划 `plan/<ISO周>.md`，推送提醒 |
| 工作日两个晚上 | JinBao | 看理论，每次约 1.5 小时 |
| 周末半天 | JinBao | 做实验，先写预测，再测量，填进记录页 |
| 周日晚上 | 定时任务 | 读本周数据，写复盘 `review/<ISO周>.md`，更新 `PROGRESS.md`，出 3 道题 |
| 随时 | JinBao | 在对话里说「出题」「讲一下 X」「帮我看这组数据」 |

## 三层检验

1. **能说清。** 合上资料讲清楚原理和原因。
2. **能算准。** 实验前在记录页填「预测功率」「预测推力」，测完看偏差。偏差在 20% 以内算过；超过 20% 要找出原因（理解错了还是测错了），写进备注。
3. **能修好。** 复盘时给出故障场景和数据，能说出最可能的原因和验证方法。

## 规则

- 安全前置五项没全部完成，计划里不安排任何下水项目。
- 一章的验收清单全部有证据，才进入下一章。证据 = 记录页里的数据，或仓库里的文件和提交。
- 一周没有任何记录：复盘不批评，问一句卡在哪，下周计划减量，只留一个最小的实验。
- 同一个验收项卡了两周：复盘里把它拆成更小的步骤。
- 每周计划的量按每周约 8 小时安排：两个晚上理论 + 周末半天实验。

## 定时任务操作说明

### 周一计划（每周一早上）

1. 克隆本仓库，读 `PROGRESS.md`、上周的 `review/<上一ISO周>.md`（如果有）、本文件。
2. 用 ArtifactData 读实验记录页的 `runs` 集合（地址见上表），了解最近做了哪些实验。
3. 用 Claude Docs 读学习路线文档里当前模块那一节。
4. 按上面的规则写 `plan/<本ISO周>.md`，格式参照已有的计划文件：本周目标、理论（两次）、实验（含要先写下的预测）、本周验收、周日复盘会看什么。
5. 更新 `PROGRESS.md` 顶部的「当前周」和「本周计划」两行。
6. 提交并推送，提交信息：`<ISO周> 计划`。
7. 给 JinBao 发一条中文短消息（手机上读）：本周目标一句话 + 最重要的三件事 + 计划文件链接。

### 周日复盘（每周日晚上）

1. 克隆本仓库，读 `PROGRESS.md`、本周的 `plan/<本ISO周>.md`、本文件。
2. 用 ArtifactData 读 `runs` 集合，挑出日期在本周（周一到周日）的记录。
3. 看本周的 git 提交。
4. 写 `review/<本ISO周>.md`：
   - 本周做了什么（按计划逐项对照：完成 / 部分 / 没做）
   - 数据结论：关键数字，预测值和实测值的偏差，偏差大的给出可能原因
   - 哪些验收项现在有证据了，可以在学习路线文档里打勾
   - 3 道题：1 道计算预测题、1 道故障诊断题、1 道原理题，答案不写在文件里，让 JinBao 在对话里回答
   - 下周建议
5. 只给有证据的项目打勾，更新 `PROGRESS.md` 的模块状态，并在「每周一句话」追加一行。
6. 提交并推送，提交信息：`<ISO周> 复盘`。
7. 给 JinBao 发一条中文短消息：本周结论一句话 + 3 道题 + 复盘文件链接。
